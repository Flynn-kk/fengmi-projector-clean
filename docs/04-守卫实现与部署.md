# 04 · 守卫实现与部署

## 结构

| 文件 | 作用 |
|---|---|
| `GuardAccessibilityService.java` | 吃 Home 键；监听窗口变化，奇异果/FallbackHome 一冒头就补刀 |
| `Launcher.java` | 拉起 Projectivy 的封装（带异常兜底） |
| `BootReceiver.java` | 开机 / 应用更新后，用 AlarmManager 在 2/6/15/30/50/65 秒各补一发 |
| `NudgeReceiver.java` | 补刀执行端 |
| `MainActivity.java` | 只为解除 stopped 状态 |

## 补刀为什么要错开时间

因为 [02](02-三条硬限制.md) 里的第 3 条：AMS 会在系统桌面启动的那几秒拒绝别的启动请求。

所以不是"拉一次就完事"，而是按一组时间点连续拉：

```java
private static final long[] BURST_MS = { 0, 500, 1500, 3000, 5000, 7500, 10000, 13000 };
```

窗口事件触发一次 `burst()`，里面按这组延时逐个 `Launcher.start()`。
同时 `burst()` 有 1.5 秒的最小间隔保护，避免窗口频繁变化时把主线程刷爆。

## 补刀要"看场合"，不能瞎拉

`NudgeReceiver` 只在**前台确实是奇异果桌面或 FallbackHome** 时才动手：

```java
if (STOCK_PKG.equals(fg) || FALLBACK_PKG.equals(fg)) { Launcher.start(ctx); }
```

否则用户正在看视频，突然被拉回桌面就太糟了。前 3 发（服务可能还没连上）允许盲拉一次。

## 部署步骤

```powershell
adb connect <PROJECTOR_IP>:5555
adb install -r .\app\guard\peppa-guard.apk

# 关键：解除 stopped 状态
adb shell am start -n com.dsh.peppa.guard/.MainActivity
adb shell input keyevent KEYCODE_BACK

# 加到无障碍列表（务必保留原来的服务）
adb shell settings get secure enabled_accessibility_services
adb shell settings put secure enabled_accessibility_services "com.spocky.projengmenu/com.spocky.projengmenu.services.ProjectivyAccessibilityService:com.dsh.peppa.guard/com.dsh.peppa.guard.GuardAccessibilityService"
adb shell settings put secure accessibility_enabled 1
```

## 验收

```powershell
# 1) 服务在不在
adb shell dumpsys accessibility | findstr /i "peppa"

# 2) 按真遥控器 Home 键 → 看日志
adb logcat -d | findstr PeppaGuard

# 3) 重启验证（最硬核）
adb shell reboot
# 开机后等 30 秒，看焦点
adb shell "dumpsys window | grep mCurrentFocus"
```

实测：连续重启 3 次（间隔约 2 分钟），全部落在 Projectivy，没有一次停在奇异果。

## 回滚

```powershell
.\app\guard\uninstall.ps1 -Device <PROJECTOR_IP>:5555
```

会先把守卫从 `enabled_accessibility_services` 里摘掉（保留 Projectivy 的），再卸载。
奇异果桌面从来没被禁用，所以不需要额外恢复。
